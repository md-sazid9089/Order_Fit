# Enable read-only platform administration

This is a controlled deployment procedure, not a startup hook. The implementation is disabled by default. Do not apply it to an assumed database target or use migration credentials in API/worker processes.

1. Identify the exact environment/database, current schema revision, restricted API login and distinct worker login. Review `0021_admin_reads` SQL and take the normal deployment backup. Upgrade through the ordinary manual migrator procedure to `0021_admin_reads`; the new API and worker require this head even when admin reads are disabled. Never roll back immutable history to disable the feature.
2. The migration creates two NOLOGIN, NOBYPASSRLS roles. `orderfit_admin_reader` owns only the five new security-definer functions, has narrow column grants and SELECT policies on four tables, and cannot CREATE in public. Its UPDATE(id) privilege plus UPDATE policy with `WITH CHECK(false)` permits row locks, not updates. Only the migrator can assume it. `orderfit_admin_api` has EXECUTE on those functions and no global table grants. Neither runtime login may inherit the function-owner role.
3. New API logins created by `orderfit.store.provision.provision_login` receive `orderfit_admin_api`; worker logins do not. For an existing API login, explicitly grant `orderfit_admin_api` to that **verified API login** through the migrator. Do not grant it to `orderfit_app` (the worker inherits that role), `orderfit_worker`, PUBLIC, or a shared database credential. No application startup code grants roles.
4. Keep `ADMIN_READS_ENABLED=false` while deploying the backend and capability-aware frontend. The local runtime launcher forwards this setting; Compose exposes it only to the API. Do not enable from the old frontend's constant flag.
5. Use a synthetic authorized platform administrator signed in after promotion. With reads disabled, `/api/v1/admin/capabilities` must report false and data reads must return 503 `ADMIN_TELEMETRY_UNAVAILABLE`. Anonymous calls must return 401; ordinary tenant owners must return 403. This API does not create/promote administrators.
6. Run the restricted-role smoke checks in the approved target: no owner/BYPASSRLS role on API/worker; API cannot become `orderfit_admin_reader`; worker cannot call `admin_read_overview`; ordinary tenant APIs deny unrelated businesses. Never print tokens, digests, passwords or private row payloads in evidence.
7. Set `ADMIN_READS_ENABLED=true` only after migration/role checks and frontend readiness. Capabilities must report true. Check a platform admin without membership can list synthetic unrelated business summaries, currencies stay separate, pagination continues, and an ordinary tenant URL still rejects access. Verify role revocation/signout and independent system checks. `/admin/logs` always remains unavailable; there are no platform mutation endpoints.
8. If the smoke checks fail, set `ADMIN_READS_ENABLED=false`, clear frontend admin data, and investigate. Leave the forward schema intact. A later permission withdrawal is also supported: missing function EXECUTE grants or required read policies make capability discovery false and data reads unavailable.

Admin reads use user-before-session authority locks. When an older session-before-user passkey flow already holds the session, the read fails promptly with a retryable dependency error; clients may retry the GET. No provider/storage health check runs while those authority locks are held.

The migration removes schema CREATE from PUBLIC/runtime roles to prevent replacement of security-definer dependencies. Review any unrelated application depending on writable `public` before a shared-database deployment. Ordinary OrderFit runtime needs no public DDL.
